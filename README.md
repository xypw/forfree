# ForFree 办公套件

一个**完全免费、离线可用**的办公工具。文字文档 / 电子表格 / 演示文稿 / PDF 工作台 / 格式转换，
全部在浏览器里跑，**不联网、不上传、数据只存本机**。
同时提供 **Windows 桌面客户端**（免安装单文件 exe）。

```
纯前端 · 无构建工具 · 无后端 · 无账号 · 无遥测
```

> **关于命名**：本项目与任何商业办公软件厂商均无关联，未使用任何第三方厂商的
> 代码、图标、模板或字体资源。所有功能均为独立实现 —— 功能本身不受著作权保护，
> 受保护的是具体实现方式，本项目不存在复制他人代码的情况。

## 打包桌面客户端

```bash
cd desktop
build.bat
```

脚本会自动完成：装依赖 → 生成图标 → 同步网页资源 → 打包到解包目录 →
写入图标与版本信息 → 生成免安装单文件 exe。产物在 `desktop/dist/` 下。

也可以分步执行：

```bash
npm install          # 首次需要，约 200MB
npm run icon         # 生成应用图标（需要 Python）
npm run sync         # 把网页资源同步到 desktop/web/
npm start            # 本地运行调试
npm run self-test    # 自动自检：逐模块截图 + 校验引擎，输出到 desktop/shots/
npm run dist         # 完整打包（= dist:dir + 打图标 + dist:portable）
```

> 国内网络建议保留 `build.bat` 里的 `ELECTRON_MIRROR` 镜像设置，否则 Electron 二进制下载会很慢。

### 打包时的三个坑（已处理，改配置时注意）

1. **`ELECTRON_RUN_AS_NODE` 必须清空**。如果这个环境变量存在，Electron 会退化成纯 Node，
   `require('electron').app` 是 undefined，启动即报 `Cannot read properties of undefined (reading 'isPackaged')`。
   `build.bat` 里已经 `set ELECTRON_RUN_AS_NODE=` 清掉了。

2. **`win.signAndEditExecutable` 必须为 `false`**。否则 electron-builder 会去下载解压
   `winCodeSign`，包里含 macOS 的符号链接，普通用户没有创建符号链接的权限，打包会中断在
   `Cannot create symbolic link`。关掉之后由 `tools/apply-icon.js` 用 rcedit 手工补图标与版本信息。

3. **不要给 `win` 配 `"sign": false`**。设了之后 `winPackager.sign()` 里
   `platformSpecificBuildOptions.sign != null` 成立，反而会去调 `doSign`，
   而 `cscInfo` 是 undefined，报 `Cannot use 'in' operator to search for 'file' in undefined`。
   不设（保持 undefined）才会直接跳过签名。

另外：`rcedit` **只能改普通 PE 文件**（`dist/win-unpacked/ForFree.exe`），
不能碰 NSIS 打出来的自解压 exe —— 它会重写 PE 结构把追加在后面的压缩数据截掉，
文件会从 68MB 变成几十 KB。所以流程必须是「先 `--dir` → 打图标 → 再 `--prepackaged` 打 portable」。

### 桌面版与网页版的关系

两者**共用同一份代码**，不是两份实现。`desktop/sync-web.js` 把根目录的
`index.html` + `assets/` + `samples/` 复制到 `desktop/web/`，桌面版启动时由
Electron 主进程起一个只监听 `127.0.0.1` 随机端口的微型 HTTP 服务来承载界面
（这样 PDF 的 Web Worker 才能正常工作），再把窗口指向它。

改网页版代码后，重新执行 `npm run sync` 或 `npm run dist` 即可让桌面版同步更新。

### 桌面版额外能力

- 原生窗口、任务栏图标、开始菜单式的应用名
- 中文菜单栏：文件（打印 / 返回首页 / 退出）、编辑、视图、窗口、帮助
- 导出文件时弹系统「另存为」对话框，保存完成后界面提示保存路径
- 单实例运行；外部链接自动交给系统浏览器打开
- 安全设置：`contextIsolation` 开启、`nodeIntegration` 关闭、渲染进程沙箱化

「关于」对话框里还有一个「打开程序所在文件夹」，方便把整个程序文件夹拷给别人。

> 关于「复制文件本身到剪贴板」：这个功能**没有做**，因为实测做不到。
> Electron 的 `clipboard.writeBuffer` 只能注册自定义剪贴板格式，无法写入 Windows 的
> `CF_HDROP`。我逐个试过 `FileNameW`、`FileName`、`text/uri-list`、`CF_HDROP`
> 四个格式名，系统都读不出来（对照测试：写图片格式 `image/png` 正常）。
> 所以改用「打开文件夹 + 原生拖拽」这两条真正能用的路。
> 拖拽走的是 Chromium 的原生 `IDataObject`，是标准做法。

### PDF 工作台

**阅读**：多页连续滚动、缩略图导航、缩放（35%–400%）、适应宽度、文本可选可复制

**批注**：文本批注（支持中文）、高亮、矩形框、椭圆圈、箭头、自由画笔、图片图章、橡皮擦

**水印**：一键为所有页面添加旋转水印文字

**页面管理**：左右旋转 90°、上移下移、删除、整体倒序、恢复原始顺序、提取当前页

**合并**：把多个 PDF 合并成一个

**压缩**：把每页重渲染成 JPEG 再重建 PDF，四档可选（极限 72 DPI / 高压缩 96 DPI / 均衡 150 DPI / 高质量 200 DPI）。对扫描件、图片型 PDF 效果最明显 —— 实测 2.1 MB 的 2 页扫描件压到 223 KB（**减小 90%**）。若压缩后反而变大，会保留原文件并提示。

**表单填写**：自动探测 PDF 里的 AcroForm 字段，在页面上按原坐标叠加可交互输入框，支持文本框、多行文本、复选框、单选、下拉列表。填写后可直接导出，或导出并扁平化（接收方不可再编辑）。

**导出**：
- 带批注的 PDF（批注真正烧录进文件，任何人打开都能看到）
- 转 Word / 转 Excel（见下）
- 原始 PDF
- 所有页面转 2 倍分辨率 PNG（zip 打包）
- 提取全部文本为 `.txt`

### PDF 转 Word / Excel

同类软件通常对 PDF 转 Word 有页数或次数限制。ForFree **不限页数、完全免费**：

- **转 Word**：按 Y 坐标把文字聚合成行 → 合并成段落；按字号自动识别标题层级；连续多单元格的行会自动识别成表格；居中的行保留居中
- **转 Excel**：按 X/Y 坐标把文字聚类成行列网格，每页一个工作表；数字自动转数值，百分比自动识别格式
- 全部在浏览器内完成，不上传、不限页数

转换完成后会弹出一个结果窗口，两个选择：

| 按钮 | 效果 |
|---|---|
| **打开编辑** | 直接切到转换出来的 Word / Excel 文档继续编辑，改完再导出回 `.docx` / `.xlsx` 或发给朋友 —— **不用先下载再重新打开** |
| **下载文件** | 只存盘，人还留在 PDF 里 |

> 局限：版式还原是启发式的，复杂排版的 PDF（多栏、图文混排、旋转文字）还原度有限。扫描件 PDF 没有文字层，转出来是空的，需要 OCR。

### 同时打开多个文件

- 首页文档列表里点 **「新窗口」** → 在另一个窗口打开这篇文档
- 编辑器标题栏点 **「新窗口」** → 再开一个窗口（停在首页），可以在里面挑另一篇
- 桌面版开的是真正的独立窗口；网页版开新标签页

每个窗口各自独立编辑，互不干扰。同一篇文档在两个窗口里同时改的话，以最后保存的为准。

## 文件读写改（往返编辑）

打开电脑上已有的 Office 文档 → 编辑 → 再导出回去：

1. 首页点「打开文件」，选择 `.docx` / `.xlsx` / `.pptx` / `.csv` / `.md` / `.html`
2. 系统在本机解析文件内容并载入对应编辑器
3. 编辑完成后点「导出」→ 选择原格式
4. 得到一个新的 Office 文件，内容与格式已更新

`.docx` / `.xlsx` / `.pptx` 的解析与生成全部在浏览器内完成（基于 fflate 解压 + 自研 OOXML 读写），不经过任何服务器。

数据全部存在浏览器 `localStorage`，清空浏览器数据会一并清除。建议重要文档及时导出为 Office 文件备份。

## 已知限制

- **PDF 改原有文字**：浏览器端做不到（需要 OCR 与内容流重排）。本工具支持的是"阅读 + 批注标注 + 加字 + 页面管理"，批注会烧录进导出的 PDF。
- **PDF 压缩会把文字变成图片**：原理是逐页重渲染，所以纯文字 PDF 压缩后不能再选中文字；扫描件、图片型 PDF 不受影响。若原文件本身很小（几百 KB 的纯文字 PDF），压缩后反而可能变大，此时会保留原文件并提示。
- **PDF 表单含中文时不能扁平化**：pdf-lib 内置字体只支持 WinAnsi，扁平化需要重建字段外观，遇到中文会失败。此时会自动降级为普通导出（值已写入，接收方仍可编辑）并提示原因。
- **PPTX 图片**：演示文稿中插入的图片在导出 `.pptx` 时会丢失（形状与文字正常导出）；导出为网页或 PNG 则图片完整保留。
- **XLSX 样式**：读取他人 `.xlsx` 时会保留数值、文本与公式，字体颜色等单元格样式不导入。
- **表格撤销**：电子表格暂不支持逐步撤销，直接编辑单元格覆盖即可。
- **文档转 PDF**：走系统打印对话框的「另存为 PDF」，中文渲染最可靠。
- **PDF 转 Word / Excel 的版式**：还原是启发式的，复杂排版（多栏、图文混排、旋转文字）还原度有限；扫描件没有文字层，转出来是空的。

## 开发备忘：两个容易踩的环境问题

1. **本地存储写满会让渲染进程静默崩溃**。自检脚本反复运行会累积大量文档与历史版本，导致 Electron 渲染进程直接挂掉，且没有任何错误输出。清理 `%APPDATA%/ForFree` 即可恢复。
2. **`capturePage()` 会抓到旧帧**。切换视图后立刻截图，拿到的往往是上一个界面。自检里截图前先 `webContents.invalidate()` 并等待约 400ms。

  cd desktop && npm run self-test   # 逐模块截图 + 引擎校验，输出到 desktop/shots/
